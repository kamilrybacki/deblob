# Hermes fresh reply — jr-slm-schema-241439 (raw, 10 parts, 2026-07-24 14:34 UTC)

## Findings

### Core judgment
A 0.5B SLM is useful in Deblob at the **semantic ambiguity boundary**, not as the schema authority.

The right division is:
```
DETERMINISTIC FACTS
parse → infer physical types → canonicalize → fingerprint → profile → detect drift

PROBABILISTIC PROPOSALS
retrieve candidates → rank semantic matches → name/describe → propose mapping → explain

DETERMINISTIC CONTROL
validate → test → classify loss → enforce policy → quarantine/approve → publish
```
Calling all three "dynamic schema inference" obscures the essential safety boundary. The SLM can identify plausible meanings; deterministic systems must control contracts.

### Where the 0.5B SLM genuinely helped
1. Human-readable schema and family naming (fingerprint proves structures differ, can't decide `{order_id,amount,currency}` = commerce.order vs payment.intent).
2. Bridging heterogeneous vocabulary (`cust_no`/`customer_id`/`buyer.identifier` where exact/edit-distance insufficient) — semantic-neighbor retrieval + umbrella candidate generation.
3. Reranking a finite candidate set — most credible when choosing among a handful of retrieved schemas/glossary terms/canonical fields, NOT inventing a global ontology (matches Magneto: lightweight retrieval narrows before expensive semantic judgment).
4. Explaining deterministic evidence (given a computed diff: "amount moved under payment, changed number→string, may now encode minor currency units") — valuable in Drift Sentinel, but changed paths/types must come from deterministic comparison.
5. Drafting normalizer specifications (aliases, path moves, enum tables, conversion suggestions).
6. Bootstrapping labels (stronger teacher → candidate examples, but weak supervision; need deterministic validation, human review, dedup, provenance, hard negatives, untouched real eval set).

### Where determinism owned the decision
Parsing/nested-path extraction (exact/reproducible); primitive/union-type inference (cheaper+more reliable than generation); canonical form/fingerprint/schema ID (identity can't change with model/prompt versions); known vs provisional (registry lookup not interpretation); source-local drift detection (exact expected-ref vs observed-ref); settle-and-sample state (explicit policy); compatibility rules (replayable/auditable); family/version publication (durable contract mutation); PII redaction/egress (prompts are not security boundaries); transform execution (generated code untrusted); bidirectional/lossless claims (require property+round-trip tests); warehouse admission (must fail closed).

**The 0.5B model did NOT catch drift.** Deblob's canonicalization, fingerprinting, candidate state, tagged Kafka headers, source-local schema comparison caught it. The SLM named/explained the change. Similarly, code generation was NOT the normalizer — the normalizer was the validated mapping IR + its deterministic interpreter/compiler. Generated output became eligible only after syntax checks, type checking, sandboxed execution, fixtures, property tests, forward→reverse verification.

### Caveats that materially affected the designs
1. **Small weights ≠ small serving memory.** KV cache, context, loaded-model count, parallel generation, queues, runtime buffers, allocator/cache behavior can dominate weights. Stable config bounded: loaded models 1, parallel inference 1, queue 64, context 4096 tokens, llama arg-cache RAM disabled, container limit 3 GiB. Handled 421 requests over 12 min, 0 errors, ~1004 MiB peak, no OOM kill. Supports **admission control**, NOT a simplistic claim that one variable caused the earlier OOM. Prompt length, output length, concurrency, model count, queue depth, memory must all be bounded independently.
2. **Unloaded ≠ unavailable.** Model unloaded after keep_alive is normal (cold-loads on demand); missing artifact / non-persistent model dir after restart is a deployment failure. Readiness should perform a bounded inference canary against the exact model + expected output contract, not merely check port/model-list. Safe degradation: SLM unavailable → deterministic discovery+tagging continue → semantic annotation pending/unknown → bounded retry or offline queue → optional heuristic display name → no automatic promotion. Fallback results marked `heuristic`/`model_unavailable`, must not inherit simulated confidence, ingestion must not create retry storm.
3. **Settle-and-sample blind window.** Settled source can temporarily retain cached tag for unsampled changed records. Detection delay ≈ sample_interval / source_records_per_second. Acceptable only when bound documented + consumers tolerate. Incompatible with "first breaking record was contained" unless hero source gets full analysis or independent writer-schema contract. SLM cannot repair this — sampling+containment remain deterministic policy.
4. **Valid JSON ≠ semantic correctness.** Pydantic/JSON Schema/constrained decoding guarantee shape/enum/bounds/required, cannot establish: amount major vs minor units; timestamp event vs ingestion time; two IDs share identity; cast lossless; moved field retained meaning. 0.5B especially prone to plausible generic labels, ontology invention, missing correspondences, confident explanations from sparse context. Constrained output validates transport, not truth.
5. **Values improve inference AND increase privacy risk.** Preferred Deblob prompt is payload-free: trusted source/domain context; field paths + physical types; null/distinct/range/length/pattern summaries; retrieved schema/glossary candidates; redacted or synthetic examples only when necessary. Redaction before prompting + allowlisted deterministic output gate. Unreviewed production values must not enter training corpora, model traces, logs, or dead-letter prompts.
6. **0.5B is not a safe free-form code generator.** Credible path: SLM proposes mapping IR → deterministic type checker → template/compiler emits code → isolated execution → fixtures+property+round-trip tests → policy/reviewer approval. Finite transform vocabulary: rename, move, cast_checked, enum_map, split, join, default. Every reverse mapping declares lossless / conditionally_lossless / lossy. No proof → lossy or blocked. Many-to-one merges, truncation, defaults, unit conversion, timezone interpretation, unchecked string→number casts can't be made safe by model confidence.

### When an SLM beats deterministic logic
Semantic (not structural) problem; retrieval bounds candidates; names/descriptions/domain language are meaningful evidence; rule-based synonyms would be unmaintainable; uncertain results can abstain/review; one decision cacheable by immutable schema ID. Good tasks: schema/family naming; glossary-term recommendations; semantic column typing; routing among known event families; ranking source→canonical field correspondences; extracting known contract from unstructured logs/docs; explaining+prioritizing deterministic drift evidence. Unit of consumption = **model calls per novel ambiguity**, not per event.

### When it is overkill
JSON/CSV primitive inference; canonicalization/fingerprints; required/optional/nullability stats; exact compatibility checks; schema-ID lookup; known aliases/approved transforms; regex/range/enum validation; every record in a stable stream; candidate retrieval already solved by lexical/embedding search. Cache accepted semantic annotations by schema ID; dedup across candidate observations.

### When it is unsafe
Require deterministic rejection or human governance when a proposal would: publish/delete a schema version; merge/split families/umbrellas; reinterpret business meaning; alter units/timezone/precision/null semantics; perform a lossy cast; execute arbitrary generated code; classify PII in a way that permits egress; widen warehouse admission; rewrite historical data; trigger external/destructive actions. Invariant: **the model may add evidence or reduce a candidate set; it may not erase contradictory evidence, weaken a guard, or make an irreversible contract mutation.**

### Fine-tuning judgment
Start with deterministic retrieval + prompt/few-shot baselines. Fine-tune the 0.5B only when the ontology is stable and accepted/rejected reviewer decisions give durable labels. Best target = bounded classifier/reranker emitting candidate ID, field correspondences, evidence categories, structured uncertainty, `abstain`. NOT trained as autonomous schema author. Training data: real reviewed positives; near-match hard negatives; renamed+nested fields; sparse-context; no-match+abstention; malformed+adversarial names; prompt-like strings in values; source-held-out+time-held-out test sets; balanced sources/classes; provenance per example. Distillation reduces labeling cost but teacher output is weak supervision; synthetic examples deduplicated+validated, must not contaminate real eval set. Evaluate the complete served artifact (base+tokenizer+adapter+quantization+prompt+output grammar+Ollama/runtime config). Metrics: top-k recall; macro-F1; abstention quality; calibration+risk–coverage; unsafe false acceptance; cold/warm latency; peak RSS; timeout+OOM rate; heuristic-degradation rate. Self-reported confidence is not calibration. Do NOT continuously fine-tune on unlabeled production drift (mixes concept adaptation with contract governance, enables poisoning+catastrophic forgetting, destroys reproducibility).

### Recommended control architecture
```
Source/Kafka
 → deterministic parser, canonical schema, profile
 → fingerprint + registry lookup
 → known schema: deterministic fast path
 → novel/ambiguous: retrieve top-k candidates
 → local 0.5B SLM proposes or abstains
 → Pydantic/JSON Schema validation
 → deterministic compatibility, privacy, domain, transform checks
 → metadata proposal / quarantine / review
 → immutable publication by governance service
```
Model process: no registry-promotion credential; no warehouse DDL permission; no direct schema-state writes; no raw Kubernetes/Vault/shell/admin tools. Controller records schema ID, candidate set, model digest, adapter, quantization, prompt/grammar version, validator outcome, policy decision, reviewer result.

## Confidence & gaps
High: determinism authoritative for physical structure/identity/compatibility/drift/privacy/publication; 0.5B strongest as bounded semantic proposal/reranking w/ abstention; retrieval+caching+constrained output+deterministic validation+governance > prompt elaboration; generated normalizers need inspectable mappings + execution/property/round-trip verification; Ollama needs bounded admission + tested degradation, ingestion can't depend on model availability.
Medium: fine-tuned 0.5B useful for naming+top-k reranking on Deblob corpus but needs source-held-out benchmark; distillation value depends on label quality+hard negatives not synthetic volume; 0.5B may draft useful mapping IR but free-form codegen likely too brittle without larger verifier + deterministic templates.
Gaps: (1) no end-to-end benchmark of served quantized artifact+abstention+unsafe-false-acceptance; (2) accuracy/privacy trade-off metadata-only vs redacted value profiles unmeasured; (3) candidate-burst latency/admission/queue need load testing; (4) cold-start/absent-artifact/restart/timeout/OOM degradation need fault tests; (5) bidirectional mapping needs corpus labeled reversible/conditionally-reversible/lossy; (6) most published schema-matching benchmarks use tables not adversarial heterogeneous event streams; (7) model confidence needs calibration vs held-out sources; (8) fine-tuning data provenance/retention/PII-scrub/deletion/memorization controls need governance design before production samples used.

Thesis: **Use the SLM to compress ambiguity into an auditable proposal; use deterministic systems to establish facts and exercise control.**
