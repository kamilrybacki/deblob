# Data sources to utilize Deblob — Joint Research Report
run: `jr-deblob-sources-181240` · 2026-07-18 · agents: Claude Code + Hermes

## Executive summary
Deblob wants **heterogeneous, drifting JSON event streams**. Two complementary corpora emerge, and the strongest plan uses both:
- **Homelab-native webhooks + telemetry [H]** — GitHub/Actions webhooks, a *sampled* slice of the JSON logs already in Loki, Argo CD + Grafana alert webhooks. Effectively free, mostly in-cluster, matches the deployed `n8n → Redpanda → Deblob` path, and drifts naturally. **Best first corpus for genuinely _using_ Deblob on real infra.**
- **External public firehoses [C]** — Wikimedia **EventStreams** (SSE, per-stream JSON Schema, Kafka-backed) and Bluesky **Jetstream** (JSON WebSocket firehose, filterable). Highest schema-diversity + volume, evolve over time, and — importantly — **Deblob's own experiment harness already has GitHub-Archive + Wikimedia ingestion adapters**, so these are the lowest-risk external paths to wire live.
- **[C+H] agreement on the ingestion rule:** keep the raw nested JSON as JSON; let n8n add only a thin envelope (`source`, `event_type`, `delivery_id`, `received_at`) under a `payload` field, and **scope family retrieval by source** so a Stripe object and a GitHub object are never candidates for the same family. Flattening erases exactly the structure Deblob exists to discover.

**Recommended first cut:** three source-scoped topics — `events.github` (owned-repo webhooks), `events.wikimedia` (EventStreams `recentchange` + `revision-create`), `events.logs.sampled` (allowlisted Loki apps). GitHub + Wikimedia give cross-family heterogeneity and real drift immediately; the Loki sample adds first-party compatible-drift as services release new fields.

## Key findings

1. **Wikimedia EventStreams is the single best external fit [C].** Continuous SSE/NDJSON, every stream has a published JSON Schema (`schema.wikimedia.org`), Kafka-backed with offset resume. `recentchange`, `revision-create`, `page-*` streams differ structurally = instant cross-family data; schema versions evolve over time = real drift. No key, no auth. Deblob already ingested Wikimedia in the experiment. Sources: wikitech EventStreams, enterprise.wikimedia realtime firehose.
2. **Bluesky Jetstream — highest-volume evolving JSON firehose [C].** `wss://jetstream2.us-east.bsky.network/subscribe`, unauthenticated, filter by `wantedCollections` (NSID) so volume is controllable. Lexicons/collections evolve → new families appear organically. Caveat: very high volume unfiltered; not self-authenticating. Sources: bluesky-social/jetstream, docs.bsky.app/blog/jetstream.
3. **GitHub repo + Actions webhooks are the best _homelab_ source [H] [C+H].** Push/PR/issue/release/check/workflow/deployment/package events have substantially different nested payloads; new actions/fields provide genuine drift. It's a supported integration on owned repos, not scraping. Preserve `X-GitHub-Event`/`X-GitHub-Delivery`, validate `X-Hub-Signature-256`, dedup redeliveries, 25 MB cap. PII: usernames, commit emails, issue text, private repo names — filter sensitive event types before retention. (Corroborated: Deblob's experiment already uses GitHub-Archive; live webhooks are the streaming equivalent.)
4. **Allowlisted Loki JSON logs — richest first-party drift, handle with care [H].** Different services/releases emit different shapes; the data already exists in-cluster via Alloy. **Do not tail all of Loki through n8n** — query only low-volume allowlisted apps, keep a timestamp cursor, sample, short Redpanda retention. Highest PII risk (tokens, bodies, IPs) — exclude auth/Vault/Secret/raw-body logs, redact before Deblob.
5. **Argo CD + Grafana alert webhooks — cheap, adjacent, already wired [H].** Sync/health/lifecycle payloads (ArgoCD) and evolving `alerts[]`/label maps (Grafana) form real deployment/alert families. Both controllers are already deployed with templated-webhook support. Use `oncePer`/fingerprint dedup so flapping isn't mistaken for novelty.
6. **Curated multi-source public streams as a diversity booster [C].** `conduktor/public-streaming-api` and `bytewax/awesome-public-real-time-datasets` catalogue key-free feeds: USGS earthquakes (GeoJSON, revisions+deletes), NWS/CAP weather alerts (lifecycle), GTFS-Realtime transit, OpenSky flights, EMSC seismic WS, crypto WS (Binance/Coinbase/Kraken), Open-Meteo. Individually narrow-schema, but pooled they add polarity/format variety and several have update/delete/revision semantics that exercise versioning. Sources listed below.

## Conflicts & adjudication
- **"#1 source" differs by goal.** Hermes ranks GitHub webhooks #1 (homelab fit); my sweep ranks Wikimedia/Bluesky highest (raw heterogeneity). Not a real conflict — different objectives. **Adjudication:** for *making Deblob useful to the homelab*, GitHub webhooks + sampled Loki win; for *showcasing schema discovery/drift*, Wikimedia EventStreams wins. The recommended first cut deliberately blends one of each (`events.github` + `events.wikimedia`), which also de-risks by reusing Deblob's existing GitHub-Archive/Wikimedia adapter lineage.
- **MQTT.** Both agents independently down-ranked public MQTT brokers (HSL transit [C] is interesting transport, but `test.mosquitto.org`/HiveMQ public [H] are unstable, unauthenticated, legally ambiguous, and likely egress-blocked). Agreed: not a corpus.

## Unverified leads
- Safe sustained volume for a curated Loki→n8n polling path (actual JSON-log rates, Redpanda retention, Deblob storage pressure not measured) [H].
- Whether Deblob can exclude the transport envelope from **fingerprint identity** (critical to the "don't flatten" rule) — needs a code check in the canonicalizer [H].
- Existing n8n workflow definitions, egress-guard rules, and webhook ingress auth were not inspected [H].
- Stripe test-clocks as a *deterministic* demo generator [H] — excellent controlled schema-evolution, but synthetic; good for a scripted demo, not organic discovery.

No MQTT broker deployed; no prior vault note on MQTT/n8n ingestion.
